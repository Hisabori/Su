# 수호천사 iOS 복원 프로젝트

원본 APK의 Flutter AOT 코드(Dart 3.8.1), 이미지 및 앱 설정을 분석해 재작성한 Flutter 프로젝트입니다. 원래 Dart 소스 파일을 그대로 추출한 결과가 아닙니다.

## 기기 패스키 로그인 (1.2.0)
지원되는 iPhone Safari/PWA에서 작업 화면의 열쇠 버튼으로 기존 세션을 패스키로 암호화할 수 있습니다. 다음에는 패스키로 잠금을 풀고 기존 서버에서 토큰을 확인합니다. 서버 수정 권한이 없어 서버 계정 자체의 패스키 로그인은 구현하지 않았으며, 세션 만료 후에는 비밀번호 로그인과 갱신이 필요합니다. 네이티브 IPA 연동은 아직 지원하지 않습니다. 사용법과 보안 범위는 [패스키 설명](docs/PASSKEYS.md)을 참고하세요.

## 웹 PWA / Vercel (1.1.0)
같은 Flutter 코드를 iOS와 웹에서 빌드합니다. HTTPS의 Safari/Chrome에서 홈 화면에 설치할 수 있습니다. 한글 글꼴과 앱 화면 파일을 함께 배포합니다.

Vercel 기존 프로젝트 `suho-angel`에서 Git 저장소를 `Hisabori/Su`로 연결하고 Root Directory를 저장소 루트로 둡니다. `vercel.json`이 Framework = Other, Build Command = `bash scripts/vercel-build.sh`, Output Directory = `build/web`를 설정합니다. 기존 프로젝트에 수동 Build/Output 값이 있다면 이 값과 일치시켜 주세요. 프로젝트가 일시 중지돼 있다면 Vercel 대시보드에서 Resume을 실행해야 합니다.

빌드 스크립트가 Flutter 3.47.7을 설치하고 고정된 pubspec.lock으로 JavaScript 웹 릴리스를 빌드합니다. 선택 환경 변수 `API_BASE_URL`은 **빌드 시** 적용되며 기본값은 기존 서버입니다. 웹 코드에 포함되므로 비밀 값을 넣지 않습니다. GitHub Actions `Web PWA Build`에서도 검사·테스트·웹 빌드를 실행하고 `suhoangel-web-pwa` ZIP을 제공합니다. ZIP은 정적 호스팅용 완성 파일이며 저장소용 빌드 스크립트와 구분하세요.

직접 빌드: Flutter를 PATH에 둔 뒤 `bash scripts/build-web.sh`. 확인: `python3 -m http.server 8080 --directory build/web` 후 localhost로 접속합니다. 호스팅 하위 경로에서는 `WEB_BASE_HREF=/경로/`를 빌드 시 지정합니다. Vercel 도메인 루트는 기본 `/`입니다.

- Safari: 공유 → 홈 화면에 추가. Chrome: 메뉴 → 앱 설치.
- 앱 화면은 서비스 워커로 캐시하지만 로그인·작업 조회·결과 저장에는 인터넷이 필요합니다. API 응답과 로그인 정보는 서비스 워커 캐시에 넣지 않습니다.
- 진행 답변은 단계 변경·백그라운드 전환 시 및 약 10초 간격으로 기기에 저장합니다. 같은 계정·배정 정보일 때 새로고침 후 복구합니다. 진행 중 체크포인트는 작업 기준 시각에서 4시간까지 복구하며, 저장 대기 결과는 만료시키지 않습니다. 마지막 저장 전 변경, OS의 강제 종료 직전 변경은 잃을 수 있습니다.
- 브라우저 데이터 삭제·시크릿 모드 종료·도메인 변경 시 기기 내 기록을 잃을 수 있습니다. 여러 탭에서 같은 작업을 동시에 진행하지 마세요.
- 영상은 재생 버튼으로 시작합니다. 마이크는 사용자 동작과 권한이 필요하며, 브라우저에 따라 음성 인식을 지원하지 않을 수 있습니다. 예/아니요 버튼으로도 답변할 수 있습니다.
- 새 버전은 기존 앱 창을 모두 닫고 다시 열면 적용됩니다. 서비스 워커가 진행 중 작업을 강제로 새로고침하지 않습니다.

## 1.0.2 안정화

- PUT 로그인, SHA-256 비밀번호 처리, 요청별 packetid, 토큰·사용자 식별자 보관
- 원본 MainActivity의 화면 꺼짐 방지를 iOS idle timer 설정으로 반영
- 저장된 세션 검증, 작업 정보 조회 및 display_order 정렬

- HTTPS 동영상·YouTube 재생, 재생 결과 기록, 백그라운드 전환 시 음성·영상 중지
- 기준 작업/휴식 시간의 반복 주기에 따른 자동 휴식
- 원본의 3시간 작업 종료 및 1시간 유예 후 로그아웃 규칙

- 원본 WorkResultPayload 형식의 서버 저장, ret=1 성공 확인

## GitHub 빌드 및 설치
main에 push하거나 Actions → iOS Sideload IPA → Run workflow를 실행합니다. macOS runner가 검사·테스트 후 미서명 IPA를 만들고 `suhoangel-unsigned-ipa` artifact로 14일간 보관합니다.

ZIP을 다운로드하여 IPA를 꺼내 AltStore 또는 Sideloadly에서 본인 Apple 계정으로 서명·설치하세요. 무료 Apple 계정은 통상 7일마다 갱신이 필요합니다. iOS 15 이상을 대상으로 합니다.

Mac에서 직접 빌드하려면 Flutter 3.47.7과 Xcode를 준비하고 `bash scripts/build-sideload.sh`를 실행하세요.

## 검증 범위와 남은 확인
API 형식은 원본 네이티브 코드에서 확인했습니다. 자동 테스트는 실제 서버 계정 대신 모의 응답을 사용합니다. 실계정 로그인, 실제 업무 배정 응답, 결과 저장 및 iPhone의 음성·영상 재생은 아직 실기기에서 검증하지 않았습니다.

화면은 추출한 이미지를 사용해 재작성했으며, 원본의 모든 레이아웃·애니메이션을 동일하게 복제한 것은 아닙니다. iOS는 기본 Flutter 앱 아이콘을 사용하며, 웹 PWA는 원본 캐릭터 이미지를 아이콘으로 사용합니다. 백그라운드에서 타이머 코드를 계속 실행하는 방식이 아니라, 앱에 복귀했을 때 현재 시각으로 상태를 다시 계산합니다. 기기 시각이 서버 시각과 다르면 일정에 영향을 줄 수 있습니다.

서버 저장 응답을 받지 못한 경우 이미 저장됐을 가능성도 있으므로 서버 기록을 확인한 뒤 재전송하세요. 원본 packetid를 재사용하지만 서버가 이를 중복 방지 키로 처리하는지는 검증하지 않았습니다.

자세한 근거는 [복원 근거](docs/RECOVERY.md)를 참고하세요.
