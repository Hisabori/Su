# 원본 / PWA 호환 점검

확인 기준: 2026-11-19 원본 APK 분석 결과와 관리 웹의 공개 `main.dart.js`.
원본 서버에 실제 결과를 쓰지 않는 모의 API / 브라우저 검사로 검증한다.

| 항목 | 원본 형식 / 동작 | PWA 처리 |
| --- | --- | --- |
| 기기 식별 | 관리 웹은 `kioskId`, `kioskID` 모두 허용 | 두 키 모두 지원 |
| 기기 조회 | APK `partnerId`, 관리 웹 `partnerIds: [...]` | 기존 요청 실패·기기/용량 누락 시 검증된 관리 웹 방식으로 1회 재조회; 인증 거절은 재조회하지 않음 |
| 근무결과 인코딩 | `result_json`은 JSON 배열을 인코딩한 문자열 | 동일 |
| 기기 확인 종류 | `type: device_check` | 동일 |
| 근무 상세 용량 열 | `기기상태체크` 문자열을 그대로 출력 | 상태 문구를 보내던 오류 수정. 정상 확인은 `25.0%` 형식 |
| 사용 불가 확인 | 원본 APK는 `사용 불가` 문자열 저장 | 동일. 그래프의 원시 용량과 사용 가능 상태는 별도로 취급 |
| 잘못된 용량 | 유효한 퍼센트로 판단할 수 없음 | 0%를 추정하지 않고 `용량 미확인` |
| 확인 시각 | `시간`, 로컬 `yyyy-MM-dd HH:mm:ss` | 동일 |
| 사용 가능 여부 | `isAvailable` boolean | 동일 |
| 과거 저장 결과 | 이미 확정된 서버 기록 | 변경·중복 전송하지 않음. 과거 상태 문구만으로 퍼센트를 복원할 수 없음 |
| 10분 그래프 | 원본 근무 상세와 별도 경로 | PWA 서버 공유 이력이며 원본 관리 웹에 그래프 전체가 자동 전송되는 것은 아님 |

## 확인 근거

- APK `KioskCapacity.checkStatus` 0x437fac: 정상 용량은 소수점 한 자리 퍼센트.
- APK `DeviceCheckRecord.toResultJson` 0x2d1f8c: `type`, `device_name`, `기기상태체크`, `시간`, `isAvailable`.
- 원본 관리 웹 `bmy`: `device_check`의 `기기상태체크`를 ‘용량’ 셀에 출력.
- 원본 관리 웹 기기 현황: 사용 가능한 기기에 현재 적재율을 표시. 근무 상세에 저장된 확인 결과와 별개임.

## 검증 범위

- `test/device_check_record_test.dart`: 0·25·100·125%, 오류·사용 불가, 실제 전송 구조.
- `test/api_contract_test.dart`: 조회 재시도, ID 변형, 용량 누락, 인증 거절.
- `test-js/collector.test.cjs`: 같은 계약을 서버 경로에서도 검증.
- `scripts/test-pwa.cjs`: 브라우저에서 기기 확인 후 결과 저장, 전송 JSON, 중복 저장 방지, 재접속·퇴근.
- 실제 사용자의 원본 관리자 화면과 DB를 로그인해서 검증한 결과는 아님. 해당 계정의 다음 정상 기기 확인·근무결과 저장 후 원본 화면에서 최종 확인이 필요함.

## 회전 검사 실패의 원인
기존 브라우저 검사는 서버 시작 시간이 09:00인데 현재 시각을 09:15로 고정한 채 홈 화면을 촬영하고 ‘작업 시작’을 누르려 했습니다. 촬영 중 1초 주기 예약 시작이 정상 실행돼 버튼이 사라졌습니다. 테스트는 촬영 시각을 08:59:50으로 분리한 뒤 09:15로 전환하여 예약 시작을 검증합니다. 제품의 예약 시작을 끄지 않습니다. 별도 위젯 검사는 하단 글래스 바가 있는 상태에서 세로→가로→세로 전환 후 작업 시작 버튼을 스크롤해 누를 수 있는지 확인합니다.
