# 수거기 서버 공유 기록과 오류 코드

새 로그인에서 기존 서버가 반환한 `company_device_name`과 `kiosk_id`를 Vercel의 비공개 세션에 보관합니다. 수거기 기록 API는 Bearer 토큰·커뮤니티 세션·기존 서버의 토큰 검증을 모두 확인하며, 클라이언트가 지정한 사용자나 다른 기기 번호로 조회할 수 없습니다.

같은 기기에 배정된 사용자는 계정이나 브라우저가 달라도 같은 서버 기록을 조회합니다. 로그인하지 않은 공개 조회는 제공하지 않습니다. 기존 로그인 세션에 배정 정보가 없으면 진행 중인 근무를 마친 뒤 다시 로그인해야 서버 연결이 활성화됩니다.

## 저장·조회 동작

- 앱이 열려 있을 때 기존 10분 조회에 맞춰 Vercel이 배정 기기의 원래 API를 직접 조회하고 Private Blob에 저장합니다. 클라이언트의 적재율·시각·사용자명은 업로드하지 않습니다.
- 같은 기기의 같은 10분 구간은 하나의 변경 불가 기록을 공유합니다. 다른 기기와 회사의 기록은 별도의 경로로 분리됩니다.
- 최근 7일 범위를 100개씩 조회합니다. `이전 서버 기록 불러오기`로 더 볼 수 있으며 그래프·요약은 불러온 기록을 기준으로 합니다.
- 앱이 모두 닫힌 동안에는 수집하지 않습니다. 기존 기기에만 있는 과거 기록을 서버 측정값으로 소급 생성하지 않습니다.
- 서버 연결 실패 시 기기 내 기록을 계속 보여주며 동기화 지연을 표시합니다. 서버 저장과 로컬 백업은 독립적입니다.
- 7일은 조회 범위입니다. Blob의 과거 객체를 자동 삭제하는 기능은 이 변경에 포함하지 않습니다.

## 수거기 오류 코드

| 코드 | 단계 | 의미 |
|---|---|---|
| DVC-000 | 저장 | 서버 조회·저장 성공 |
| DVC-001 | 인증 | 서버 기기 세션 없음·만료·확인 실패 |
| DVC-002 | 배정 | 세션의 기기 배정 정보 없음, 새 로그인 필요 |
| DVC-003 | 요청 | 허용하지 않은 요청 항목 또는 잘못된 페이지 위치 |
| DVC-101 | 원래 기기 API | 수거기 조회 연결·응답 실패 |
| DVC-102 | 기기 검색 | 배정된 수거기를 응답에서 찾지 못함 |
| DVC-103 | 측정값 | 용량 정보가 없거나 유효하지 않음 |
| DVC-201 | 서버 읽기 | 서버 기록 목록·객체 조회 실패 |
| DVC-202 | 서버 쓰기 | 측정 결과의 서버 저장 실패 |
| DVC-203 | 클라이언트 연결 | 기록 API 네트워크 연결·시간 초과 |
| DVC-204 | 응답 해석 | 서버 기록 형식 또는 배정 일치 확인 실패 |

조회 실패를 0%로 기록하지 않습니다. 실패 표본은 `error`와 `error_code`가 있고 용량은 미확인으로 남으며 평균에서 제외됩니다. 같은 10분 구간에는 최초 표본을 사용하므로 실패 표본도 다음 구간 조회 전까지 그대로 표시될 수 있습니다.

## 진단 이벤트 구체화

`suho_diagnostic`에는 `trace`, `area`, `code`, `error_id`, `stage`, `severity`, 서버 수신 시각이 기록됩니다. 구버전 클라이언트가 `error_id`를 보내지 않아도 서버가 코드표로 생성합니다. 새 클라이언트의 오류 ID가 코드표와 다르면 수신을 거절합니다.

오류 ID 접두사는 `AUTH`(세션), `WORK`(근무기록), `DEVICE`(기기 로컬 기록·서버 연결)입니다. 번호는 `101` 읽기 실패, `102` 저장 실패, `103` 복구 백업 실패, `104` 세션 복원 실패, `105` 로그인 거절, `010` 손상 행 복구, `000` 로그인 성공, `001` 자동 로그인 복원 성공입니다. 예: `WORK-101`, `AUTH-102`.

`collector_sample`은 서버가 실제 조회·저장한 표본의 처리 결과입니다. `collector_error`는 서버 기록 API의 오류 코드와 처리 단계입니다. 클라이언트와 서버의 이벤트는 같은 `trace`로 연결되며, `collector_history`는 조회한 표본 수를, `collector_sample`은 처리 시간을 함께 남깁니다. 기기는 원본 이름 대신 해시한 `device_ref`로 구분하며 비밀번호·토큰·사용자명·게시글 내용은 진단 로그에 포함하지 않습니다. `suho_diagnostic`은 클라이언트 보고이므로 인증된 사용자 행위의 감사 증거로 취급하지 않습니다. 로그 보존 기간은 Vercel 요금제 설정을 따릅니다.
