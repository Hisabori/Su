# 기기 패스키 세션 잠금 (1.2.0)

기존 API 서버를 수정할 수 없어 **서버 계정의 WebAuthn 가입·인증 API는 추가하지 않았습니다.** 서버가 패스키 공개키와 서명을 검증해서 새 세션을 발급하는 방식과 다릅니다. 기존 비밀번호 로그인으로 받은 유효한 세션을 WebAuthn PRF로 암호화하고, 같은 기기/브라우저에서 패스키 인증으로 복호화한 뒤 기존 서버의 `validate_token`으로 확인합니다. 비밀번호나 비밀번호 해시는 저장하지 않습니다.

## 사용

1. 기존 아이디·비밀번호로 로그인합니다.
2. 작업 화면의 열쇠 버튼 → `이 기기에 패스키 설정`을 선택합니다. 패스키 제공자에 따라 등록과 최초 잠금 해제에 인증을 두 번 요청할 수 있습니다.
3. 작업 화면에서 `앱 잠그기`를 누르면 서버 로그아웃 없이 메모리의 세션을 비웁니다. 새로고침/창 종료 후에도 잠깁니다. 다음에는 `이 기기 패스키로 로그인`을 선택합니다.
4. 서버 세션이 만료되거나 서버 로그아웃으로 무효화됐다면 비밀번호로 다시 로그인하고 패스키 설정에서 `로그인 정보 갱신`을 선택합니다. 무기한 비밀번호 없는 계정 로그인이 아닙니다.

지원 조건은 HTTPS, WebAuthn, user verification, PRF를 지원하는 브라우저와 패스키 제공자입니다. iPhone에서는 Safari 또는 홈 화면 PWA에서 시도할 수 있지만 iOS 버전·제공자별 실제 지원 여부는 등록 시 확인합니다. PRF가 없으면 원래 비밀번호 로그인을 사용하며 암호화되지 않은 토큰 보관으로 자동 대체하지 않습니다. 가상 Chromium 인증기로 검증했으며 물리 iPhone/Face ID는 아직 검증하지 않았습니다.

네이티브 IPA에서는 이 패스키 기능을 지원하지 않습니다. 네이티브 연동에는 Apple Associated Domains/서명 구성과 해당 인증기의 PRF 연동이 추가로 필요합니다. 앱은 웹 버전을 여는 안내를 제공합니다.

## 저장 및 제한

- WebAuthn PRF 32바이트 결과 → HKDF-SHA-256(원본 도메인과 용도 분리) → 비추출 AES-256-GCM 키.
- 매 저장마다 무작위 12바이트 IV를 사용합니다. 버전·origin·credential ID·salt·사용자 ID를 인증된 추가 데이터로 묶습니다.
- 디스크에는 credential ID, salt, IV, 사용자 ID, 암호문만 기록합니다. PRF 값, AES 키, 비밀번호를 기록하지 않습니다. 복호화된 액세스·갱신 토큰은 현재 창의 메모리에만 있습니다.
- 최초 등록 후 예전 `flutter_secure_storage`의 세션 사본을 제거하고 확인합니다. 기존 작업 기록과 체크포인트는 제거하지 않습니다.
- 브라우저 데이터와 패스키가 모두 있어야 합니다. iCloud 등으로 패스키를 다른 기기에 동기화하더라도 암호문은 옮겨지지 않습니다.
- 백그라운드 전환만으로 자동 잠기지 않습니다. 자리를 비울 때 `앱 잠그기`를 사용합니다. 열린 상태의 악성 스크립트/XSS나 기기 전체 침해를 막는 기능은 아닙니다.
- 서버가 유효한 토큰을 가진 다른 클라이언트를 패스키 없이 차단하는 정책은 추가되지 않았습니다. 작업 기록 자체의 암호화 정책도 변경하지 않았습니다.
- 지원하지 않는 제공자로 등록을 시도하면 제공자에 사용하지 않는 패스키가 남을 수 있습니다. 기기의 비밀번호 관리자에서 직접 삭제할 수 있습니다. 앱의 설정 해제는 로컬 암호문만 지우며 제공자의 패스키는 지우지 않습니다.

서버 계정 자체의 패스키 로그인을 원하면 서버에 일회용 challenge 저장·소모, RP ID/origin 검증, UV 및 서명 검증, credential 공개키 저장·폐기, 기존 계정과의 안전한 연결, 서버 세션 발급을 추가해야 합니다. 이 클라이언트 잠금을 서버 인증 대체로 간주하지 않습니다.

## 검증

- `scripts/test-passkey-vault.cjs`: 실제 WebAuthn 가상 CTAP2.1 인증기의 PRF로 등록·재시작 후 복호화, 다른 계정 덮어쓰기 거절, 세션 갱신, 변조된 암호문 거절, 취소 및 PRF 미지원 처리.
- `scripts/test-passkey-flow.cjs`: Flutter UI에서 모의 API 로그인 → 패스키 등록 → 구 토큰 삭제 → 앱 잠금 → 패스키 해제와 서버 세션 확인 → 새로고침 잠금 → 만료 세션 거절 → 갱신·설정 해제.
- `test/session_storage_test.dart`: 세션 내보내기·복원·기존 사본 제거와 작업 기록 보존, 잘못된 세션으로 기존 로그인을 지우지 않음.

브라우저 테스트는 Playwright 1.58.2와 Chromium을 사용하며, `NODE_PATH`와 `CHROMIUM_PATH`를 실행 환경에 맞춰 설정합니다. UI 검증 전에 `build/web`를 로컬 8765 포트로 서빙합니다. 모든 토큰·비밀번호는 가짜 테스트 값입니다.

GitHub Actions의 Web PWA Build는 `scripts/ci-browser-tests.sh`에서 고정된 Playwright 버전과 runner의 Chrome으로 패스키 및 기존 작업 흐름을 함께 검사합니다.
